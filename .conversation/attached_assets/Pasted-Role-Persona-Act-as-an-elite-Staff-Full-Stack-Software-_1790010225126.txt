1. TECH STACK & DEPLOYMENT TARGET (Vercel-Ready)
--------------------------------------------------
- Framework: Next.js (App Router, TypeScript, React Server Components + Server Actions / Route Handlers).
- Styling & UI: Tailwind CSS, Radix UI / Shadcn UI primitives, Framer Motion for micro-interactions.
- Database & Auth Layer: Supabase (PostgreSQL with Row-Level Security) or Neon Serverless Postgres with Drizzle ORM. (Recommended: Supabase handles serverless auth, DB, and object storage out-of-the-box with zero cold-start/connection-pool bottlenecks on Vercel).
- Document Storage: Cloudflare R2 or Supabase Storage (S3-compatible, presigned URLs for secure upload/download). Do NOT store files directly in local disk storage since Vercel is stateless.
- Session Management: HttpOnly, Secure, SameSite=Strict long-lived JWT session cookies (persists until manual logout).

--------------------------------------------------
2. CORE FUNCTIONAL REQUIREMENTS
--------------------------------------------------
A. Authentication & Session:
- Phone/Email OTP Authentication:
  - Users sign up / log in by entering their mobile number or email to receive a 6-digit OTP.
  - Rate limiting on OTP generation (e.g., max 3 attempts per 10 minutes per IP/identifier to prevent SMS/email bombing).
  - Secure session token issued upon OTP verification, stored in an HttpOnly, Secure, SameSite=Strict cookie.
  - Persistent Session: The session must remain authenticated indefinitely until the user explicitly clicks "Log Out".
- Route Guarding:
  - Middleware-level route protection (`/dashboard/*`, `/admin/*`, `/documents/*`).
  - Unauthenticated requests are immediately redirected to `/login`.

B. Document Management (User Workspace):
- Upload Document:
  - Drag-and-drop or file picker.
  - Required fields: Title, Category/Tags (e.g., ID Proof, Financial, Medical, Academic, Contracts), Notes/Description.
  - File Validation: Strictly validate MIME types (PDF, PNG, JPEG, WEBP) and enforce file size caps (e.g., max 15MB) both client-side and server-side.
  - Sanitization: Strip dangerous metadata and generate UUID/randomized file keys before storage.
- Document Display & Viewer:
  - Responsive Grid / List view with instant search, category filters, and sort by date/name.
  - Card UI includes thumbnail/default icon preview based on file type, upload date, file size badge, and direct actions.
  - Secure In-App Preview: Embedded PDF viewer and image modal powered by short-lived pre-signed read URLs (never expose direct public S3 URLs).
  - Actions: Rename, edit tags, download, and soft-delete/permanent delete.

C. Multi-Tenancy & Data Isolation:
- Absolute tenant separation: Every user must ONLY query, view, modify, and delete their own documents.
- Database must enforce user-level scoping on all queries (or PostgreSQL Row-Level Security: `auth.uid() = user_id`).
- Prevent Insecure Direct Object References (IDOR): Any request requesting a document by ID must verify document ownership before resolving.

D. Admin Panel:
- Role-Based Access Control (RBAC): `USER` vs `ADMIN`.
- Admin Dashboard Overview: Total registered users, total documents stored, storage metrics, and audit activity logs.
- User Management: List all users, toggle user status (Active / Suspended / Deactivated), view per-user storage quotas.
- Admins can manage account status, but cannot view private user documents unless explicitly granted audit permissions (zero-trust privacy model).

--------------------------------------------------
3. ARCHITECTURE & SOLID PRINCIPLES
--------------------------------------------------
- Single Responsibility (SRP): Decouple API handlers, service layers (DocumentService, AuthService, StorageService), and UI presentation components.
- Open/Closed (OCP): Build an abstract StorageProvider interface (e.g., `uploadFile`, `getPresignedViewUrl`, `deleteFile`) so storage can switch between Supabase, Cloudflare R2, or AWS S3 without changing business logic.
- Liskov Substitution & Interface Segregation (LSP & ISP): Minimal, clean interfaces for repositories and auth providers.
- Dependency Inversion (DIP): High-level modules must depend on abstractions (e.g., `IDocumentRepository`), not concrete database drivers.

--------------------------------------------------
4. SECURITY HARDENING CHECKLIST
--------------------------------------------------
1. OWASP Top 10 mitigation:
   - CSRF protection via SameSite cookies.
   - XSS protection via input sanitization (Zod schemas for all request payloads) and Content Security Policy (CSP) headers.
   - Content-Disposition headers set to `inline` or `attachment` with `X-Content-Type-Options: nosniff`.
2. Rate Limiting: Apply Upstash Redis / Vercel KV rate-limiting middleware to all sensitive endpoints (OTP request, OTP verify, upload).
3. Secrets & Env Vars: Zero hardcoded secrets. Rely strictly on `.env` (`DATABASE_URL`, `STORAGE_SECRET_KEY`, `AUTH_SECRET`, etc.).
